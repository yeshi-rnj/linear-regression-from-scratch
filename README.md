# Linear Regression from Scratch (NumPy only)

A linear regression model built entirely from scratch with NumPy — hypothesis
function, MSE cost function, and gradient descent — with no `sklearn.linear_model`
anywhere inside the implementation. scikit-learn is used only at the end, as an
independent sanity check.

## Dataset

I originally planned to use California Housing, but `fetch_california_housing()`
downloads from an external file host that wasn't reachable in my environment, so
I used scikit-learn's **built-in diabetes dataset** instead: 442 patients, 10
numeric baseline health measurements (age, sex, BMI, blood pressure, six blood
serum markers) as features, and a continuous target (a quantitative measure of
disease progression one year later). It ships with scikit-learn, has no missing
values, and is a good fit for regression since every feature is already numeric.

## The math

### Hypothesis

For `m` examples and `n` features, with a bias/intercept column of 1s prepended
to `X` (so `X` is `m × (n+1)` and `theta` is `(n+1) × 1`):

```
h(X) = X · theta
```

This single matrix multiplication computes predictions for every example at
once — it's the same formula whether there's 1 feature or 10.

### Cost function (Mean Squared Error)

```
J(theta) = (1 / 2m) * sum( (h(X) - y)^2 )
```

The `1/2` is a convenience factor: it exists purely so that when you take the
derivative, the `2` from the squared term cancels it out, leaving a clean
gradient. It doesn't change *where* the minimum is, only the exact numeric value
of the cost at that minimum.

### Gradient

Differentiating `J(theta)` with respect to `theta` gives:

```
dJ/dtheta = (1 / m) * X^T · (h(X) - y)
```

Intuitively: for each parameter `theta_j`, the gradient is the average, over all
examples, of the prediction error multiplied by that feature's value. Features
that are more responsible for the error (large `x_j`, large error) get a bigger
push.

### Gradient descent update rule

```
theta := theta - alpha * dJ/dtheta
```

Repeated for `n_iterations` steps, using **all** training examples each step
(batch gradient descent — not stochastic/mini-batch). `alpha` is the learning
rate. Too high and the cost oscillates or diverges; too low and it converges
too slowly. I used `alpha = 0.5` on standardized features, which gave smooth,
fast convergence (see plots below).

### R² (coefficient of determination), computed manually

```
SS_res = sum( (y_true - y_pred)^2 )        # residual sum of squares
SS_tot = sum( (y_true - mean(y_true))^2 )  # total sum of squares
R^2 = 1 - SS_res / SS_tot
```

R² compares the model's errors against the trivial baseline of "always predict
the mean." 1.0 is a perfect fit, 0.0 means the model does no better than
predicting the mean, negative means it does worse.

```bash
pip install -r requirements.txt
python train.py
```

This prints training progress, saves the plots into `plots/`, and writes
`results.json`.

Features were standardized (zero mean, unit variance, fit on the training set
only) before training. Train/test split was 80/20 (`random_state=42`).

### Simple linear regression (single feature: BMI)

BMI is the single strongest individual predictor of disease progression in this
dataset, so it's used to demonstrate the single-feature case.

| Metric | Scratch (NumPy) | scikit-learn |
|---|---|---|
| Test MSE | 4061.826 | 4061.826 |
| Test R² | 0.2334 | 0.2334 |
| Coefficient | 47.1411 | 47.1411 |
| Intercept | 153.7365 | 153.7365 |

Identical (to floating-point precision) — with a single feature the loss
surface is simple enough that 2000 iterations fully converges to the same
optimum scikit-learn finds analytically.

### Cost convergence

Gradient descent cost drops smoothly and monotonically from ~14,856 to ~1,434
over 2000 iterations for the multi-feature model (see
`plots/cost_convergence_multi.png`), and similarly for the single-feature model
(`plots/cost_convergence_simple.png`). No oscillation or divergence, which
confirms `alpha = 0.5` is a good learning rate for this (standardized) data.

`plots/predicted_vs_actual.png` shows test-set predictions plotted against
actual values, with the y=x line for reference.

## Notes / design choices

- **Standardization**: features are standardized using only training-set mean/std
  (then the same mean/std applied to the test set) to avoid test-set leakage,
  and because gradient descent converges far more reliably when features are on
  comparable scales.
- **Batch gradient descent**: every iteration uses the full training set, not a
  mini-batch, since the dataset is small (442 rows) and this keeps the cost
  curve smooth and easy to reason about.
- **`sklearn.model_selection.train_test_split`** is used only for the split
  itself, per the assignment's rules — no `sklearn.linear_model` or
  `sklearn.metrics` is used inside `linear_regression.py`.
